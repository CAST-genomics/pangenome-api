The 120-Second Tube Map

The /seqtubemap endpoint takes two minutes to return a 10 MB SVG for a 10 kb region — and while it does, it takes the entire API down. Measured against the live service at pangenome-api.ucsd.edu, with server-side stage timings and a local harness.

A dated measurement — and, since 2 September 2026, a historical one

This is what the service did on 27 August 2026, and it is the baseline everything since is read against. It is no longer what the service does. The server moved to main on 2 September 2026 and stayed there, so increments A, B and C are all live: A made the endpoints synchronous, so one slow request no longer stalls the others; B deleted the browser emulation this document diagnoses, so the import:jsdom+canvas, jsdom:construct-dom and serialize:outerHTML stages below no longer exist; and C replaced the d= path strings section 03 weighs with the numbers behind them, and published them as a second format the app now reads.

So the numbers below are before numbers with no after beside them. Neither live window produced one — 31 August and 2 September were both looks rather than measurements, and no stage timings were captured during either. Sections 01 and 06 are the two that want re-running, and nothing is stopping that now except somebody doing it.

Every main.py line reference below is as of 27 August 2026 and all of them have since moved — read them as "this is the code that was measured", not as pointers to follow.

Two readings matter here. Track count never moves — 464 at every region size, because that is the haplotype count, and it multiplies everything downstream. And time is wildly nonlinear and noisy: 1,000 bp came back faster than 300 bp. That inversion is the one piece of caching in the system leaking through — preprocess_gfa_subgraph is the only artifact checked with .exists(), so a previously-touched region skips the most expensive upstream step.

02Where the time is not

A local harness runs the Node half of the pipeline in isolation, mirroring generate-svg.mjs stage for stage. On a synthetic graph of 36,106 elements — twice the size of the real 3,000 bp response — the entire Node stage completes in 1.44 seconds:

The server spent 35.3 s producing a smaller graph than this, so most of the time had to sit upstream of SVG generation. That reasoning was right about where and wrong about how much: §06 now carries server-side timings, and upstream is 30.1 s of a 38.9 s request — close to the 34 s inferred here — but SVG generation is 8.2 s, not 1–2 s. This harness understates the server's Node stage by 4–8×, and the gap widens with region size. Trust §06 over this section.

Note the first three lines. 722 ms of that total is fixed cost — booting JSDOM, node-canvas, and importing 130 KB of tubemap.js — paid on every single request no matter how small the region.

03Findings

One slow request takes down the whole API

Measured

seqtubemap is declared async def, but every call inside it is blocking: four synchronous subprocess.run invocations plus the gbz extraction. That blocks the FastAPI event loop outright. This was confirmed by accident — four unrelated requests issued while the 120 s call was in flight all failed with no HTTP status at all, then succeeded immediately once it finished. Concurrent requests don't queue, they die.

main.py:452 · blocking calls at :250, :273, :293

Path aggregation is implemented, but effectively never fires

Measured

The pathnumoption=compressed option groups haplotypes into path_summary keyed on walk_update — the entire node traversal across the whole region, as one string. Two haplotypes collapse only if their walks are byte-identical end to end, so a single SNP anywhere in the window keeps them apart. At 1,000 bp, compressed and normal returned byte-identical 1,300,847-byte responses: nothing collapsed.

This is aggregation at the wrong granularity. Collapsing tracks that agree between branch points, rather than across the entire walk, is what would actually merge those 464 lanes — and is closer to what a tube map is meant to draw.

main.py:212–226

Most of the payload is repeated strings, not geometry

Measured

In the real 90 bp response: style= is 14% of bytes (fill: rgb(211, 211, 211); fill-opacity: 1; written out hundreds of times) and trackName= is 13% — each track's full name, e.g. NA20806#1#CM102444.1#0[80060344-80060632], duplicated per element. Actual path geometry d= is only 8%. There are 599 <title> elements for tooltips against 517 <rect>s.

A browser is emulated server-side to emit XML

Measured

To run the browser visualization component on the server, generate-svg.mjs stands up a full JSDOM document with pretendToBeVisual: true, plus a node-canvas instance whose only job is backing a monkey-patched getComputedTextLength for text measurement — then discards all of it and takes .outerHTML as a string. Nothing is rasterized; the cost is DOM emulation, and it is the 722 ms fixed floor on every request.

The caveat: the layout math in create() is real work that has to happen somewhere. What is gratuitous is routing it through a DOM — not that it happens.

seqtubemap/generate-svg.mjs

Result caching is not the fix

Ruled out

The code deletes every intermediate and the finished SVG after each response, so identical repeat requests recompute from scratch — 3.18 s then 3.01 s for the same region. That looked like an easy win, but scientists poke arbitrary nodes across a loaded graph and rarely repeat a specific retrieval, so a cache would almost never hit. Ruled out on access-pattern grounds.

05The harness

Four files in perf/, no genomics toolchain required — they exercise the JSON→SVG boundary directly, so none of data.path, tools.path, or the HPRC graph files need to be provisioned.

  • gen-vg-json.mjs — deterministic synthetic vg JSON: reference spine, bubbles, haplotypes. Tunable spineNodes, haplotypes, bubbleRate, altFreq, seqLen, seed.
  • stage-timer.mjs — mirrors generate-svg.mjs stage for stage, timing each and measuring output composition. Runs as its own process, because tubemap.js holds module-level layout state. Emits progress to stderr so a crash still names the stage that died.
  • bench.mjs — sweeps one graph dimension at a time; --input=real.json takes a real fixture.
  • cross.mjs — the tracks × nodes cross term, which is the case that matters.
node perf/stage-timer.mjs <input.json> <out.svg> <start> <end> <nodeWidthOption>
node perf/bench.mjs --axis=spine
SPINES=40,150,600 HAPS=464 ALT=0.08 node perf/cross.mjs

perf/fixtures/ is gitignored — the sweeps generate hundreds of MB.

The slow stage is one Python loop, not gbz-base

Measured

subgraph_extract wraps two calls: the gbz-base query, and GenerateWalksMC, which adds W lines. The query prints its own timing on the line above — Used 0.042 seconds. That is 0.042 s of the 30.077 s. The rest is a Python loop doing one tabix fetch per segment across 464 haplotypes, at a flat 65–79 ms per segment across three orders of magnitude of region size. A constant that size is per-iteration overhead, not an algorithm that grows — which makes it the most tractable win on the server, and it is in our own code rather than in a dependency.

The vg round trip costs nothing

Measured

gfa_to_vg + vg_to_json is 0.63 s of the 10 kb request — 1.6%. Deleting the two subprocess spawns and two temp files buys back six tenths of a second out of thirty-nine. The case for removing it survives on provisioning and architecture grounds; it is no longer a performance item, and it drops to last in the plan. This measurement was taken to decide whether it was the first real fix. It is the last.

SVG generation is superlinear, and takes over at scale

Measured

2.6 → 4.3 → 8.2 → 91.0 s against 0.43 → 3.64 → 11.59 → 41.0 MB of JSON. From 11.6 MB to 41 MB, 3.5× the data costs 11× the time. The cached 35.9 kb row is the proof case: extraction skipped entirely, and it still took 93.6 s, 97% of it in SVG generation. Caching buys nothing at large spans, because the stage it skips is not the one that dominates there — and the case for removing the browser is larger than §02 estimated, not smaller.

With these numbers, nothing in this report is inferred by subtraction any more. Note also the floor: a 13-node, 90 bp region still spends 2.65 s in generate_svg. That is §02's 722 ms of JSDOM boot and tubemap.js import, measured on server hardware at roughly 3.5×. No region is served faster than that while the browser emulation stands.

Measured 27 Aug 2026 against pangenome-api.ucsd.edu:8000 and locally on Node v26.7.0 / darwin 25.5.0. Live-API timings are single samples on a shared service and carry real variance; the local harness is deterministic and repeatable.
